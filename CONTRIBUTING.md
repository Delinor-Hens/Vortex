## 1. Обзор архитектуры

Vortex состоит из трёх основных компонентов:

- **Ядро на C++ (`vortex_core.dll`)** – отвечает за сетевое взаимодействие с Ollama, HTTP-клиенты для облачных провайдеров, хранение чатов и настроек, шифрование ключей, генерацию ответов (включая потоковую). В новых версиях используется libcurl вместо WinHTTP для кроссплатформенности.
- **Графический интерфейс на Python (Tkinter)** – обеспечивает пользовательский интерфейс, включая чат, редактор кода, вкладку плагинов, мини-игры, темы и агентский режим. Поддерживает Markdown и LaTeX разметку.
- **Установщик** – два варианта:
  - `vortex_setup.exe` – классический WinAPI-установщик, распаковывает data-файлы и настраивает Ollama.
  - `Setup.exe` – единый автономный файл, содержащий внутри `vortex_setup.exe`, `data0` и `data1`; не требует внешних файлов.

Связь между Python и C++ осуществляется через `ctypes` (файл `gui/core_wrapper.py`).

## 3. Настройка окружения разработчика

### 3.1. Установка MinGW-w64

Рекомендуется использовать [MSYS2](https://www.msys2.org/) или standalone сборку [WinLibs](https://winlibs.com/).  
Убедитесь, что `g++`, `gcc`, `windres` и `objdump` доступны из командной строки.

### 3.2. Установка Python

Необходим Python 3.10+ (64-bit). Установите и добавьте в PATH.

### 3.3. Установка PyInstaller

```bash
pip install pyinstaller
```

### 3.4. Установка Git

Для управления версиями используйте [Git for Windows](https://git-scm.com/).

### 3.5. Установка libcurl (для Windows)

Если вы не хотите статически линковать libcurl, необходимо установить динамическую библиотеку. В MSYS2 выполните:

```bash
pacman -S mingw-w64-ucrt-x86_64-curl
```

Затем файл `libcurl-4.dll` появится в `C:\msys64\ucrt64\bin\`. Он потребуется для сборки и запуска.

## 4. Сборка C++ DLL (vortex_core.dll)

Выполните в корне проекта (`Vortex/`) в **cmd** (не PowerShell):

```cmd
cd /d E:\Vortex
g++ -O2 -shared -o build\vortex_core.dll core\src\api_bridge.cpp core\src\llm_engine.cpp core\src\memory_store.cpp core\src\text_processor.cpp core\src\providers.cpp -DVORTEX_CORE_EXPORTS -std=c++11 -mwindows -static-libgcc -static-libstdc++ -Wl,-Bstatic -lstdc++ -lwinpthread -Wl,-Bdynamic -lws2_32 -lcurl -Icore/include
```

### Пояснение флагов

- `-shared` – создать DLL.
- `-DVORTEX_CORE_EXPORTS` – макрос для экспорта функций.
- `-std=c++11` – стандарт C++.
- `-mwindows` – отключить консольное окно.
- `-static-libgcc -static-libstdc++` – встроить GCC-рантайм.
- `-Wl,-Bstatic -lstdc++ -lwinpthread -Wl,-Bdynamic` – статически слинковать libstdc++ и pthread.
- `-lws2_32 -lcurl` – системные библиотеки и libcurl (заменил WinHTTP).
- `-Icore/include` – путь к заголовкам.

## 5. Сборка автономного exe (PyInstaller)

```cmd
python -m PyInstaller --onefile --windowed --noconfirm --add-binary "build/vortex_core.dll;build" --add-binary "build/libcurl-4.dll;build" --add-data "assets;assets" --add-data "config.json;." vortex.py
```

**Примечания:**
- `libcurl-4.dll` нужна только если DLL слинкована динамически. Если вы используете статическую линковку, эту строку можно убрать.
- `--noconfirm` позволяет перезаписывать файлы без запросов.
- Результат: `dist\vortex.exe`.

## 6. Лаунчер Vortex.exe

Если используется `vortex_launcher.cpp`, соберите его:

```cmd
g++ -O2 vortex_launcher.cpp -o Vortex.exe -municode -mwindows -static -lole32 -lshell32 -luuid -lshlwapi -lcomctl32
```

Лаунчер обычно запускает `dist\vortex.exe`. Убедитесь, что путь корректен.

## 7. Сборка установщика vortex_setup.exe

```cmd
g++ -O2 vortex_setup.cpp -o vortex_setup.exe -municode -mwindows -static -lole32 -lshell32 -luuid -lshlwapi -lcomctl32 -loleaut32 -lurlmon
```

Установщик выполняет:
- Проверку наличия Vortex.
- Установку Visual C++ Redistributable.
- Установку Ollama (через winget или скачивание).
- Загрузку модели qwen3.5:4b.
- Создание ярлыков и запись в реестр.

## 8. Обновление data-файлов установщика

1. Удалите старые `data0` и `data1`.
2. Положите рядом с `vortex_setup.exe` папку `Vortex`, содержащую:
   - `Vortex.exe` (лаунчер или PyInstaller exe)
   - `dist\vortex.exe`
   - `build\vortex_core.dll`
   - `assets\`
   - `config.json`
3. Запустите `vortex_setup.exe` – он пересоздаст `data0/data1`.

## 9. Проверка зависимостей

После сборки DLL выполните:

```cmd
objdump -p build\vortex_core.dll | findstr "DLL Name"
```

**Должны остаться только системные DLL:**
- `KERNEL32.dll`
- `USER32.dll`
- `api-ms-win-crt-*`
- `libcurl-4.dll` (если динамическая линковка)
- `WS2_32.dll`

**Не должно быть:**
- `libgcc_s_seh-1.dll`
- `libstdc++-6.dll`
- `libwinpthread-1.dll`

Аналогично проверьте `dist\vortex.exe` и `vortex_setup.exe`.

## 10. Единый файл-установщик (Setup.exe)

Для создания полностью автономного установщика, который не требует внешних файлов, используется `vortex_pack_builder.cpp` и `vortex_single_pack.cpp`.

### 10.1. Подготовка

Положите в одну папку:

- `vortex_setup.exe`
- `data0`
- `data1`
- `vortex_single_pack.cpp`
- `vortex_pack_builder.cpp`

### 10.2. Сборка инструмента

```cmd
g++ -O2 vortex_pack_builder.cpp -o vortex_pack_builder.exe -std=c++17
```

### 10.3. Генерация Setup.exe

Запустите `vortex_pack_builder.exe`. Он:

- Проверит наличие `vortex_setup.exe`, `data0`, `data1`.
- Сгенерирует `embed.s` с помощью `.incbin`.
- Скомпилирует `embed.s` в `embed.o`.
- Соберёт `Setup.exe`, объединив `vortex_single_pack.cpp` и `embed.o`.

После успешной сборки появится `Setup.exe` — единый самодостаточный файл.

### 10.4. Принцип работы Setup.exe

При запуске Setup.exe:

1. Извлекает встроенные файлы во временную папку.
2. Запускает `vortex_setup.exe` с правами администратора.
3. Ждёт завершения установки.
4. Удаляет временные файлы.

Пользователю не нужны ни компиляторы, ни Python, ни библиотеки.

## 11. Автоматический сборщик build_tool

Для удобства разработки созданы:

- `build_tool.cpp` – консольный сборщик, автоматизирует все шаги.
- `build_gui.cpp` – графическая оболочка с прогресс-баром.

### 11.1. Сборка build_tool

```cmd
g++ -O2 build_tool.cpp -o build_tool.exe -std=c++17
```

### 11.2. Сборка build_gui

```cmd
g++ -O2 build_gui.cpp -o build_gui.exe -municode -mwindows -static -luser32 -lgdi32 -lshell32 -lcomctl32
```

### 11.3. Использование

- `build_tool.exe --target windows` – полная сборка для Windows.
- `build_tool.exe --target linux` / `macos` – создаёт пакет исходников для сборки на целевой ОС (требуется соответствующий инструментарий).
- `build_gui.exe` – окно с кнопками выбора платформы и галочкой «Без архива» для портативной версии.

Все артефакты копируются в `E:\Vortex\Vortex Setup`.

## 12. Агентский режим и генерация проектов

Агентский режим активируется галочкой **"Agent mode"** в вкладке "Код" (по умолчанию он включен всегда).  
Он работает по следующему алгоритму:

1. Пользователь вводит задачу и язык.
2. Модель получает запрос: *"Напиши полный код программы на языке X, решающий задачу Y. Верни только код. Никаких пояснений."*
3. Во время генерации агент принудительно включает режим `thinking` (неограниченная длина ответа).
4. Ответ очищается от markdown-обёрток и сохраняется в файл `main.<ext>` внутри папки `Projects/project_<timestamp>`.
5. Код загружается в редактор, но **не запускается автоматически**.
6. Пользователь может запустить программу вручную кнопкой «▶ Запустить» или «▶ Запустить код из поля». При запуске в стандартный ввод передаётся пустая строка, чтобы программы с `input()` не падали с `EOFError`.
7. Если программа завершилась с ошибкой (Traceback, SyntaxError и т.п.), активируется кнопка **«🛠 Исправить»**. При нажатии агент отправляет текст ошибки модели и получает исправленный код, который записывается в тот же файл и загружается в редактор.
8. Пользователь видит подробный отчёт о каждом шаге.

Все проекты сохраняются в папке `Projects` рядом с исполняемым файлом.

## 13. Мини-игры и экран загрузки

- При запуске приложения показывается полноэкранный оверлей с буквой **V** и анимацией "Загрузка модели...".
- Если прогрев длится дольше 10 секунд, автоматически открывается окно с мини-игрой (Змейка, 2048, Крестики-нолики).
- При долгом ответе (более 15 секунд) мини-игра также появляется.
- Игры реализованы в `gui/minigames.py`.

## 14. Работа с изображениями и файлами

Пользователь может прикреплять изображения и текстовые файлы.

- Изображения кодируются в base64 и отправляются в Ollama (поле `images`).
- Текстовые файлы читаются и добавляются в промпт.
- Для облачных провайдеров изображения пока не поддерживаются (только Ollama).

Реализация находится в `gui/main_window.py` (кнопка 📎) и `core_wrapper.py` (метод `send_message_with_images`).

## 17. Шифрование API-ключей

API-ключи провайдеров хранятся в зашифрованном виде с помощью Windows DPAPI (`CryptProtectData` / `CryptUnprotectData`).

- При сохранении ключ шифруется и записывается в файл `vortex_chats.txt`.
- При загрузке ключ расшифровывается.
- Реализация в `core/src/memory_store.cpp`.

## 18. Markdown и LaTeX в чате

Виджет чата (`gui/chat_widget.py`) поддерживает:

- **Жирный**, *курсив*, `код`, ```блоки кода```.
- Заголовки `#` – `######`.
- Формулы LaTeX: `$...$`, `$$...$$`, `$$$...$$$` и т.д.
- Автоматическая очистка от управляющих символов и исправление потерянных обратных слэшей (`\frac`, `\sqrt`, `\pm` и др.).

Исправления в C++ (`llm_engine.cpp`) гарантируют, что escape-последовательности `\f`, `\b` не превращаются в управляющие символы.

## 20. Часто встречающиеся ошибки

### 20.1. `libgcc_s_seh-1.dll not found`
**Причина:** динамическая линковка GCC-рантайма.  
**Решение:** использовать `-static-libgcc -static-libstdc++`.

### 20.2. `libwinpthread-1.dll not found`
**Причина:** не статически слинкована библиотека pthread.  
**Решение:** добавить `-Wl,-Bstatic -lwinpthread -Wl,-Bdynamic`.

### 20.3. `0xc00000ff` при запуске
**Причина:** использование `std::locale("")` в `memory_store.cpp`.  
**Решение:** удалить все вызовы `file.imbue(...)`.

### 20.4. `api-ms-win-crt-*` отсутствует
**Причина:** нет Universal C Runtime.  
**Решение:** установить Visual C++ Redistributable (установщик делает это автоматически).

### 20.5. `Модель не успела загрузиться`
**Причина:** слишком маленький таймаут.  
**Решение:** в `llm_engine.cpp` увеличено число попыток до 10 и пауза до 10 секунд.

### 20.6. `не удалось разобрать JSON` в агентском режиме
**Решение:** агентский режим теперь не требует JSON. Он просто запрашивает код и сохраняет его в файл.

### 20.7. Ошибка `Could not find module 'vortex_core.dll'` при запуске из исходников
**Причина:** отсутствует `libcurl-4.dll` рядом с DLL или в PATH.  
**Решение:** скопируйте `libcurl-4.dll` в папку с `vortex_core.dll` или соберите DLL со статической линковкой libcurl.

### 20.8. PyInstaller не может найти `libcurl-4.dll`
**Решение:** скопируйте `libcurl-4.dll` в папку `build` перед запуском PyInstaller или добавьте `--add-binary`.

### 20.9. Не удаётся извлечь встроенные файлы в Setup.exe
**Причина:** возможно, `embed.s` не был корректно скомпилирован или `windres` не включил ресурсы.  
**Решение:** используйте `.incbin` через ассемблер (как в `vortex_pack_builder`). Убедитесь, что файлы `data0`, `data1` и `vortex_setup.exe` находятся в той же папке, что и `embed.s`.
